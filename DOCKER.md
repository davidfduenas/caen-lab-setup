# Running everything in containers (Docker)

Three containers, started with Docker Compose:

| Service | What it is |
|---|---|
| `influxdb` | InfluxDB 1.8, database `NOvA_DTG_CAEN` created automatically |
| `grafana` | Grafana, with the InfluxDB data source already configured |
| `daq` | ROOT, the built DAQ programs, the HV monitor, tmux and the launchers |

## Requirements
- A **Linux x86-64** machine with Docker and Docker Compose, for real hardware. The CAEN libraries and the ROOT base image are x86-64 only. On macOS, Windows or ARM you can build and test the software side, but USB devices cannot be passed through in the usual way.
- The **CAEN libraries**, which you download yourself (registration required). They are not in this repository or in any image. See `docker/caen/README.md`.
- On the host, the udev rule that names the HV supply `/dev/ttyDT5471P0` (see `DAQ_Caen/SETUP.md`, section 6).

## Build and start

```bash
git clone --recursive https://github.com/davidfduenas/caen-lab-setup.git
cd caen-lab-setup

# put your CAEN library archives into docker/caen/ (see docker/caen/README.md)

docker compose build
docker compose up -d
```

For real hardware, add the overlay, which passes the USB devices and your display through:

```bash
docker compose -f docker-compose.yml -f docker-compose.hardware.yml up -d
```

The overlay fails to start if `/dev/ttyDT5471P0` does not exist on the host. Plug in and name the supply first.

If you build without the CAEN archives, the image still builds but the DAQ programs are not compiled. The build prints a warning, and the file `/opt/lab/NO_CAEN_LIBRARIES` exists inside the container. Add the archives and run `docker compose build` again.

## Use

```bash
docker compose exec daq hv-session      # HV supply: three tmux panes (monitor, voltage, current)
docker compose exec daq daq-session     # digitizer: temperature monitor plus two panes for runs
docker compose exec daq scope           # live waveform viewer (needs the overlay and `xhost +local:docker` on the host)
```

Take runs in a `daq-session` pane exactly as described in `DAQ_Caen/SETUP.md`, section 8. The `daq` container starts in `/opt/lab/DAQ_Caen`, so `./daq_threshold_v1.0.0 -n 100 -m sw -c 0 -r 1500 --txt data/test.txt` works as written.

- **Data and logs** are written to `./data` and `./logs` next to `docker-compose.yml`. The container runs as root, so these files are owned by root on the host.
- **Grafana:** <http://localhost:3000>, login `admin` / `admin` (change it at first login). The InfluxDB data source is already set up.
- **InfluxDB:** `localhost:8086`, reachable from the host only.
- Detach from tmux with `Ctrl-b d`. The session keeps running while the container runs.

## Stop

```bash
docker compose down        # stops the containers, keeps the InfluxDB and Grafana data
docker compose down -v     # also deletes the InfluxDB and Grafana data
```

## Changing settings

Edit the `environment:` block of the `daq` service in `docker-compose.yml` (for example `INFLUX_DB`, `HV_SERIAL_PORT`, `TEMP_INTERVAL`). All variables are listed in the `tmuxsessions` README. If you change the Influx database name, also change `INFLUXDB_DB` in the `influxdb` service and `database:` in `docker/grafana/provisioning/datasources/influxdb.yml`.

## What was and was not tested

Tested (on an ARM Mac, with the amd64 images emulated):
- the image builds without the CAEN libraries
- all three services start
- the database is created and the Grafana data source is provisioned
- a point written from the `daq` container is read back through Grafana
- the tmux session starts inside the container
- the HV Python dependencies and the scope viewer's dependencies import
- the CAEN install helper runs install scripts in order, with dummy packages

Not tested:
- installing the real CAEN packages (the helper expects each package to contain an install script, such as `install_64`; if your package layout differs, the build stops with an error that lists the folder)
- compiling the DAQ programs against the real CAEN libraries
- USB access from the container to the real digitizer and HV supply, including whether the CAEN USB library needs a driver on the host
- the live viewer through X11
